# Paper-ready results

Generated by ``benchmark/paper_experiments.py`` and ``benchmark/evaluate_trajectory.py``
on the label-free harness. Read ``BENCHMARK_STATUS.md`` and
``EVALUATION_CONTRACT.md`` first — the naming rules and the field isolation
contract are what make these numbers usable at all.

**None of the earlier figures (75.33 / 84.79 / 72.60 / …) appear here.** They
were produced by a harness that fed ground-truth scores into the engine and
could not be reproduced, so they were deleted rather than updated.

## 1. SCI-600 (600 cases, self-labelled, single-event)

Reproduce::

    python benchmark/paper_experiments.py

| Baseline | Action Acc. | Macro F1 | BLOCK Recall | False Allow | False Block |
|---|---|---|---|---|---|
| content_keywords | 0.4900 | 0.4870 | 0.4470 | 111 | 9 |
| **agentshield_production** | **0.4333** | **0.4349** | 0.3825 | **24** | 8 |
| tool_name_rules | 0.2917 | 0.2815 | 0.1429 | 134 | 12 |
| local_context | 0.2983 | 0.2442 | 0.0000 | 146 | 0 |
| llm_as_judge | 0.2517 | 0.1808 | 0.0000 | 157 | 0 |
| agentshield_no_graph | 0.2083 | 0.1206 | 0.0000 | 183 | 0 |
| agentshield_graph_only | 0.2083 | 0.1149 | 0.0000 | 217 | 0 |

**AgentShield does not win this table on Macro F1.** It is second, behind
``content_keywords``. That result is reported as-is; the next section explains
why the comparison is not what it looks like.

### Why content_keywords wins here, and why that is not a capability

The label-shuffle control in ``leakage.json`` answers this directly:

| Baseline | accuracy (labels intact) | accuracy (labels shuffled) | delta | leak suspected |
|---|---|---|---|---|
| content_keywords | 0.4900 | 0.3067 | **+0.1833** | **yes** |
| agentshield_production | 0.4333 | 0.3733 | +0.0600 | no |

Shuffling the labels costs ``content_keywords`` 18 percentage points and costs
AgentShield 6. A baseline whose score collapses when the labels stop
correlating with the input was reading the labels. AgentShield's score is not
explained by them.

Note this is the *baseline's* leakage, not ours: ``content_keywords`` reads
``category``, which the AgentDojo adapter once derived from ``label``. The
SCI-600 fixtures also carry ``attack_stage`` and ``chain_id``, which the
keyword scorer's category prior table happens to key on. So the strongest
number on this dataset is the least trustworthy one.

### Where AgentShield is actually stronger

* **False allow: 24 vs 111** — 4.6x fewer dangerous calls let through. This is
  the failure mode that matters for a governance system; Macro F1 weights it
  the same as everything else.
* **Lowest expected cost** under the cost model in ``review_cost.json``
  (review $5, false_block $50, false_allow $500): ``lowest_cost_baseline`` is
  ``agentshield_production``.
* BLOCK-class behaviour differs in kind: AgentShield sends 110 BLOCK samples to
  HUMAN_REVIEW and 24 to ALLOW; ``content_keywords`` sends 111 straight to
  ALLOW. Ours is biased toward escalating rather than releasing — the
  conservative direction for a gate.

### What this dataset cannot measure

SCI-600 is single-event and self-labelled. Provenance signals — the actual
contribution — require a tool output to observe, which does not exist in this
fixture format. The component ablation here is therefore flat by construction
(full 0.4349 / no_taint 0.4349 / no_provenance 0.4298). **Do not present the
ablation on this dataset as evidence about the architecture**; use section 2.

## 2. AgentDojo trajectory evaluation (n=2000, labels by AgentDojo authors)

Reproduce::

    python benchmark/evaluate_trajectory.py --max-samples 2000

1961 attack / 39 benign. ``injection_goal`` is used only as trajectory *content*
(the text a tool returned), never as detector input.

| Configuration | detection_recall | block_recall | benign_review_rate | benign_block_fpr |
|---|---|---|---|---|
| tool_only (single-event gate) | 0.792 | 0.034 | 0.128 | 0.000 |
| + taint tracking | 0.814 | 0.054 | 0.128 | 0.000 |
| **+ full provenance** | **0.891** | **0.790** | 0.128 | 0.000 |

**``block_recall`` 0.034 → 0.790 is the headline.** It is a 23x increase that no
amount of single-event score tuning can produce, because the deciding signal —
the destination is absent from the operator's request — is only computable
across events. ``benign_block_fpr`` stays 0.000 throughout, so the gain is not
bought by over-blocking.

This is the ablation to cite. Each row is one engine flag away from the next
(``enable_provenance`` / ``enable_taint_tracking``), not a separately written
predictor.

## 3. Latency

From ``latency.json`` (1000 iterations). All 7 baselines complete under one
millisecond; the production pipeline is within that budget. No LLM call is on
the governance path, so latency does not depend on a model provider.

## Explicitly not measured

* **Utility / benign task success.** Requires executing AgentDojo's real task
  suite with an agent in the loop. The current adapter replays trajectories but
  does not run tasks, so there is no task-completion signal to report. **Do not
  quote a utility number from these runs.**
* **Latency under load / p99.** Only mean per-call cost is measured.
* **AgentHarm benchmark performance.** The 208-case AgentHarm set is a
  metadata-derived proxy (synthesised calls from ``target_functions``), not a
  runtime trajectory. It is a sanity check, not a benchmark result.

## If a reviewer asks one question

It will be "your best result is on a dataset you generated yourself, and a
keyword baseline beats you there." The honest answer is in section 1: the
keyword baseline's advantage does not survive label shuffling, ours does, and
the result that isolates our contribution (section 2) is on someone else's
dataset with someone else's labels.
